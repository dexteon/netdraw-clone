  <action>
    Append a new script section delimited by the comment marker `/* ---- config ingestion ---- */` (and a matching close marker) inside index.html's existing script tag, AFTER all prior sections. Implement these pure functions with NO DOM access and NO state mutation — they take text/doc in and return data out:

    1. parseRunningConfig(text) → {devices, links, warnings}: line-by-line state machine. `hostname <name>` sets the current device hostname (one config = one device; if multiple hostname lines appear, last wins — record a warning). `interface <name>` opens an interface block on the current device (store name; handle sub-interfaces like Gi0/1.10 by keeping the full name). Within a block: `description <text>` attaches to the current interface; a line containing `shutdown` sets interface.shutdown=true; `!` closes the block. Lines outside any interface block that are not hostname/interface are skipped silently (router bgp, access-list, vlans, etc.). Bounded loop: cap total lines at 50000 to prevent giant-file DoS; if exceeded, push a warning and stop. After parsing all devices, derive links via the peer heuristic: for each interface description, normalize tokens — uppercase, split on whitespace and underscores, strip leading prefixes TO, LINK, UPLINK, P2P — then exact-match (case-insensitive) against the set of known device hostnames. A match creates a link {from: deviceHostname, to: matchedHostname}. Non-matching descriptions push a warning object {device, interface, description, reason: "no peer match"}. Placeholder nodes for unmatched peers are OFF by default (warnings only). No regex with backtracking; use indexOf/split/trim.

    2. mapAssetType(type) → TYPES key: lowercase the input; map router→router type, firewall→firewall, switch→switch, server→server; everything else → the generic node type from the TYPES catalog. Return the TYPES key string, not the object.

    3. parseAssetsJSON(doc) → {assets, warnings}: accept either a string (JSON.parse it, catching syntax errors into warnings) or an already-parsed array. Empty array → {assets:[], warnings:[]}. For each object, map fields by first-hit across key families: name from name|hostname|asset_name; type from type|category|class; ip from ip|address|mgmt_ip; group from site|zone|branch|location|group. Sanitize keys: if any asset object key is __proto__ or constructor, drop it and warn (prototype-pollution guard). Each asset becomes {name, type, mappedType (via mapAssetType), ip, group}. Preserve source array order.

    4. parseAssetsCSV(text) → {assets, warnings}: empty/whitespace string → {assets:[], warnings:[]}. Parse a header row then data rows with a quoted-field-aware splitter (handle "..." quoting, doubled quotes for escapes, commas inside quotes) — a ~25-line hand-rolled splitter, no dependency. Map header names to the same key families as parseAssetsJSON. Each row → same asset shape. Sanitize label values: if a cell's trimmed value starts with =, +, @, or a tab/newline followed by = (CSV formula injection), prefix it with a single quote or strip the leading char and push a warning. Preserve row order.

    5. buildIngestNodes(parsed, opts) → {nodes, edges, zones}: convert parsed devices or assets into the node shape Phase 1 uses (id, label, type, x, y). For running-config: one node per device (label=hostname, type from device type guess or generic), edges from parsed.links. For CMDB: one node per asset (label=name, type=mappedType), no edges. Group field values → zones: collect distinct group values in first-appearance order, assign ZONE_COLORS cyclically, each zone = {id, label, color}. Layout: place nodes on a simple grid (e.g., 200px spacing) — exact coordinates are fine; the editor's pan/zoom + fit handles the rest. This function is pure: it does not call commit() or renderAll().

    Do NOT add any UI, menu entries, modal, or event handlers in this task — that is plan 05-02. Do NOT mutate the global state object. All five functions must be reachable by name in the eval'd section so the test harness can call them.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Denial of Service | parseRunningConfig | high | mitigate | bounded line loop capped at 50000 lines; no regex backtracking (indexOf/split/trim only); giant paste pushes a warning and stops |
| T-05-02 | Tampering | parseAssetsCSV label values | high | mitigate | CSV formula-injection sanitizer: strip or single-quote leading =/+/@ on imported cell values; push warning |
| T-05-03 | Elevation of Privilege | parseAssetsJSON asset keys | high | mitigate | prototype-pollution guard: drop any asset object key named __proto__ or constructor and warn |
| T-05-04 | Denial of Service | parseAssetsJSON/parseAssetsCSV | medium | mitigate | size cap on parsed input (e.g. reject strings > 5MB with a warning); empty input returns empty without crashing |
| T-05-05 | Information Disclosure | warnings array | low | accept | warnings include device/interface/description from the user's own pasted input — no exfiltration, stays in-process |

ASVS L1: sanitization of untrusted parsed input (CSV injection, prototype pollution, size caps) satisfies input-validation requirements at the parser boundary. No high-severity threat is left without a mitigation.
