## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user paste/upload → openIngestModal | untrusted text/file content enters the modal; parsed by 05-01 functions (already sanitized at parser boundary) |
| applyIngest → state | parsed data crosses into the editor's state model only on explicit Replace/Merge confirm |
| uploaded filename → modal display | untrusted filename rendered in the DOM (path-traversal risk in display) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-06 | Denial of Service | openIngestModal paste/upload | high | mitigate | 5MB size cap on paste text and uploaded file; refuse to parse beyond cap with in-modal warning |
| T-05-07 | Tampering | uploaded filename in modal display | medium | mitigate | sanitize displayed filename: strip ../, ..\\, leading slashes; use basename only |
| T-05-08 | Repudiation | applyIngest undo-ability | medium | mitigate | applyIngest calls commit() before renderAll so the ingest is undo-able via Ctrl+Z (the prior state is on the undo stack) |
| T-05-09 | Denial of Service | rapid repeated Parse clicks | low | accept | parse is fast and bounded by the parser caps; re-parsing is idempotent (pure functions) |
| T-05-10 | Tampering | applyIngest merge dedup | high | mitigate | merge dedupes by normalized hostname/id; identical ingest applied twice via Merge yields the same final state, not duplicates (idempotency) |

ASVS L1: size cap, filename sanitization, and undo-able apply satisfy the input-validation and audit requirements at the UI boundary. No high-severity threat is left without a mitigation. Parser-boundary threats (T-05-01..05-04) are mitigated in plan 05-01 and not re-listed here.
</threat_model>
