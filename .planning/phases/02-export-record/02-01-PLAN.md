    - gifLZW(8, pixels): returns a Uint8Array of LZW-compressed data-sub-blocks for one frame of 8-bit indexed pixels. Initial code size 9, CLEAR=256, EOI=257, dictionary Map keyed (prev<<8)|c, 12-bit max codes, CLEAR resets dictionary when full, LSB-first bit packing with acc/nbits accumulator, final partial-byte flush.
    - gifAssemble(W, H, palette, indexFrames, delayCS): returns a Blob (type image/gif) with header GIF89a, logical screen descriptor with global color table flag 0xF7 and 256-entry table (palette padded to 256 with [0,0,0]), NETSCAPE2.0 loop-forever application extension, per-frame GCE with delay and disposal byte 0x04, image descriptors at offset 0,0, LZW min code size 8, data in sub-blocks of at most 255 bytes, trailer byte 0x3B.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user label text → SVG export | Diagram labels authored by the user are serialized into the exported SVG/PNG/GIF; an XSS-payload label would become SVG text content (not innerHTML) so it is structurally safe, but attribute-injection in a label is possible if Phase 1 renderers ever use setAttribute with untrusted text |
| object URL lifecycle | createObjectURL/revokeObjectURL pairs across download and svgToImage; a missed revoke leaks memory (DoS-via-long-session) but is not a network boundary |
| GIF frame pixel data | a huge canvas (e.g. 4000x3000 diagram) produces 20 frames of millions of pixels; unbounded frame dimensions can OOM the tab (resource exhaustion) |
| MediaRecorder mime | not in this plan (plan 02-02) — listed for boundary completeness |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information disclosure | cloneLayerMarkup / SVG export | low | accept | Exported SVG contains exactly the diagram the user built and explicitly chose to export; there is no secret material to disclose. Label text is serialized as SVG text nodes via textContent/outerHTML of the cloned layer (Phase 1 renderers own the escaping discipline); this plan reuses those renderers and does not introduce a new injection sink. |
| T-02-02 | Denial of service | exportGIF frame buffer | medium | mitigate | Cap GIF frame canvas dimensions to a sane maximum (e.g. 1600x1200 export bounds) and document the cap in a toast if exceeded; sample only frames 0 and 10 every 28th pixel (already specified) to bound palette cost. |
| T-02-03 | Tampering | GIF encoder byte layout | low | accept | The encoder writes a Blob the user downloads; a malformed GIF only fails to open in the user's viewer (no remote consumer). Validated informally end-of-phase by opening the file. |
| T-02-04 | Repudiation | download helper | low | accept | Downloads are a deliberate user action (menu click); no audit log is required for a single-user local app. |
| T-02-05 | Information disclosure | object URL leak | low | accept | A missed revokeObjectURL is a memory leak over a long editing session, not a data-exfil path. The plan specifies revoking on load/error (svgToImage) and after 4000ms (download); ASVS L1 does not require URL-revoke hardening beyond this. |

ASVS L1 disposition: no high or critical threats in this plan. All severities are low/medium and accepted or mitigated as above; no block-on-high triggered.
</threat_model>
