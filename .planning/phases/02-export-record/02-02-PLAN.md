<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mic hardware → MediaStream | getUserMedia grants microphone capture; the recorded audio crosses from the user's hardware into the local recording pipeline (permission-gated, browser-mediated) |
| music file → AudioContext | a user-chosen local file is decoded locally by AudioContext; zero network exfiltration possible (TS-5 honored by construction) |
| MediaRecorder mime negotiation | isTypeSupported/detectRecFormats chooses the container/codec; an unsupported or malformed mime could throw at MediaRecorder construction |
| offscreen canvas frame pump | 33ms pump rebuilds the full SVG per frame; on a huge viewport this is CPU-heavy (resource exhaustion) |
| object URL lifecycle (music) | the music file's object URL must be revoked on stop or it leaks memory across sessions |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-06 | Information disclosure | mic capture / getUserMedia | medium | mitigate | Only request getUserMedia when audioMode is mic (never on page load); on stop, stop every track so the browser mic indicator disappears immediately; failure degrades to video-only with a toast, never silently records nothing. |
| T-02-07 | Tampering | MediaRecorder mime selection | medium | mitigate | Mime candidates come only from the fixed REC_FORMATS literal filtered by MediaRecorder.isTypeSupported; wrap MediaRecorder construction in try/catch and fall back to the next supported format (or abort with a toast if none) — user input never constructs mime strings. |
| T-02-08 | Denial of service | frame pump on large viewports | low | mitigate | Cap the offscreen canvas scale at min(1.5, devicePixelRatio) to bound per-frame pixel cost; the in-flight building guard prevents decode queue buildup. |
| T-02-09 | Denial of service | object URL leak (music file) | low | accept | A missed revoke is a long-session memory leak, not a data exposure; the plan mandates revoke in stopRecording. ASVS L1 requires no further hardening for a single-user local app. |
| T-02-10 | Elevation of privilege | record UI | low | accept | The record UI only reads Phase 1 view state and calls local Web APIs; no privileged surface is exposed. |

ASVS L1 disposition: no high or critical threats. All severities low/medium with mitigate or accept dispositions; no block-on-high triggered.
</threat_model>
